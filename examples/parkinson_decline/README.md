# Example: securing collaborative Parkinson's prognosis

This example is the motivating use case for TrustFed. Eight simulated
movement-disorder centers jointly improve a **rapid decline** classifier without
sharing patient records. The focus is the **integrity** of that collaboration:
TrustFed keeps the shared model correct — and keeps unapproved code out — when
some centers are compromised or malicious.

## Run it

```bash
python examples/parkinson_decline/run_demo.py
```

It takes a couple of seconds and prints every number it claims. Nothing in this
directory is pre-computed.

## What it shows

The script runs five sections:

1. **Attacks and defenses.** A scenario table over `fedavg`, `median`,
   `trimmed_mean`, `multi_krum` and `norm_clip` under static poisoning
   (`scaling`, `sign_flip`). Naive FedAvg collapses under sign-flipping; the
   robust rules contain the attack at a cost of a few hundredths of AUC against
   the clean baseline — they bound the damage, they do not restore the baseline
   exactly. Read the printed table for the run you actually did: this section
   deliberately quotes no numbers, because the only valid source for them is the
   script's own output (it prints a copy-paste `README block` for that purpose).
2. **Adaptive attacks.** The same rules against
   `trustfed.attack.adaptive.AdaptiveAdversary`, which observes the honest
   updates and picks a strategy for the specific aggregator in use. This is the
   row that matters: a defense that only survives attacks designed before it
   existed has not been tested. Norm clipping, in particular, bounds an
   attacker's influence but does not remove it, and the adaptive row shows the
   cost of that.
3. **Attestation.** With attestation on, the code-tampered sites are rejected
   before aggregation (watch the `rejected` column), so even FedAvg stays clean.
4. **Reputation-weighted selection.** Per-site reputation after training under
   attack, next to the ground truth of who was poisoning. Reputation is
   behavioural evidence, not proof — honest sites with unusual case-mix drift
   down too, and the script says so.
5. **Automated quality report.** The Component 5 analyzer runs over a bundle
   built from the trained model and prints the report a reviewer would read.
   The demo bundle deliberately omits one model-card section so you can see a
   check fire.

Exact numbers depend on the seed (`SEED` at the top of the script) and on your
numpy version; re-running with the same seed reproduces them exactly.

## The data is synthetic

Feature names imitate a prognostic setting (age, disease duration, UPDRS-III,
MoCA, gait speed, …) but every value is randomly generated by
[`trustfed/data/synthetic.py`](../../trustfed/data/synthetic.py) from a seed, and
the names carry no empirical relationship to real measurements. **No patient
data is used.** To run on a real cohort, see [`docs/DATA.md`](../../docs/DATA.md).

## Tune it

Edit the constants at the top of `run_demo.py` (`ROUNDS`, `LOCAL_EPOCHS`,
`N_SITES`, `N_MALICIOUS`, `SEED`) or the `scenarios` list to try other
aggregators (`fedavg`, `median`, `trimmed_mean`, `krum`, `multi_krum`,
`norm_clip`, `centered_clipping`) and attacks (`none`, `gaussian`, `sign_flip`,
`scaling`, `model_replacement`, `label_flip`, `adaptive`).

For the full grid across every aggregator, attack and attacker count — with JSON
and Markdown output — use the shared benchmark harness instead:

```bash
python -m trustfed.benchmark --out results/
```
