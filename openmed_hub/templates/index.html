How it works

  1. Register your institution and stand up a node: generate a key, complete the verification handshake.
  2. Submit a bundle: weights, a Mitchell-style model card, an evaluation report, an optional clinician-readable fine-tuning manual. The pipeline attestation is checked against the approved code identities.
  3. Automated gate runs seven checks (card completeness, metadata, lineage attestation, metrics, subgroup gaps, membership-inference leakage, parameter norm). A failing check blocks the case with the reason logged.
  4. Review board: reviewers from other institutions sign approve / reject / block. No site certifies its own model. Certification needs {{ settings.certification_k }} approvals from {{ settings.certification_min_institutions }} institutions including {{ settings.technical_reviewers_min }} technical and {{ settings.clinical_reviewers_min }} clinical reviewers.
  5. Certified base: the release gets a citable identifier naming every contributor and reviewer, and anyone registered may download it and fine-tune it. Derived models link to their parent, so lineage is verifiable back to the root.
  6. Reciprocity: to receive a multi-site evaluation, a site serves as evaluator for others. Acknowledged service is signed by the counterparty and counted on the credit ledger.
